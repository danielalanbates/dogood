## Pipeline
1. Pick ranked issue → fork → clone → anti-AI / CLA checks → Fable fixes.
2. Heuristic quality gate (`QUALITY_GATE_THRESHOLD`, 25%) pre-filters.
3. `Solver._acceptance_review`: separate `claude -p --model claude-fable-5-1` call scores the diff 0–100 as a strict maintainer. Any failure → 0 → not posted.
4. ≥95 → `approvals.request` texts Daniel; push + `gh pr create` run only after "yes <n>".
5. PR safety still applies: 10/day cap, close-ratio pause, 1 PR/repo/24h.

## Known issues
- Fable usage limit surfaces from the SDK as `error result: success`; now classified as billing → 5h pause + auto-resume.
- Reviewer is conservative: a trivially-correct one-line fix scored 88% in testing, so posts will be rare. Calibrate by comparing scores to real merge outcomes (`feedback.py` pr_outcomes) before lowering.
- 95% is a model self-estimate, not a measured probability.

## Pathways
- Calibration: log review scores into `contributions` and fit against merged/closed history.
- Delegate cheap sub-work (issue triage, codebase summaries) to free models (Gemini, OpenRouter free) while Fable stays the driver/decider.
- Second independent reviewer (different model family) requiring both ≥95.

## 2026-09-13 additions
### Telegram control via the Philanthropy bot
- `src/telegram.py` reads the bot token from DaemonManager `bots.json` (role `philanthropy`, override `DOGOOD_TELEGRAM_ROLE`) and the chat id from that bot's launchd plist. The old env token was the Communications bot's token and clashed with that daemon.
- New launchd job `com.batesai.dogood.telegramd` (KeepAlive) polls the bot. **Conflict:** if DaemonManager's own `com.batesai.philanthropy.telegramd` is started, both poll the same token and Telegram returns 409; only one can receive messages.
- Commands, handled without AI: `status`, `start`, `stop`, `pending`, `yes <n>`, `no <n>`, `help`. Replying to a request message with a bare yes/no uses that message's #id.
- Anything else goes to Gemini (`gemini-flash-latest`, key from DaemonManager `secrets.json`), which can answer from a status snapshot or map the message to a command.

### Approval queue (`src/approvals.py`)
Every GitHub write is queued: new PRs, review-revision pushes plus the thank-you comment, feedback comments, and PR closes. Emoji reactions were disabled rather than queued. Approved commands run in order; a successful PR updates `contributions` and the daily PR cap.
- Caveat: prepared branches live in `/tmp/dogood-workdir`; a reboot before approval loses them and "yes" will fail.

### Menu bar app (`menubar-app/`)
- Icon rendered into `button.image` (subviews don't show on macOS 26); bundle id `com.batesai.dogood-factory` (old id was hidden by macOS).
- Icon states: green animated = working, amber = alive but paused on a limit, red = a daemon is down.
- "AI Models" dropdowns write `shared/dogood_models.json`; `config.primary_model()` and `reviewer_model()` read it on each call. Claude ids only.

### Pathways
- Run the conversation inside DaemonManager's Philanthropy daemon instead (a Do Good skill) to remove the 409 conflict.
- Batch approvals ("yes all") once the reviewer's confidence is calibrated against merge outcomes.
